# Разработка КАР-точки

Краткая инструкция для тех, кто дорабатывает проект: настройка окружения, git, тесты и локальный запуск.

## Первоначальная настройка

1. **Склонируйте репозиторий** (или откройте папку проекта в Cursor).

2. **Создайте локальный конфиг Supabase** — файл `js/config.js` не хранится в git:
   ```bash
   cp js/config.example.js js/config.js
   ```
   Откройте `js/config.js` и впишите `SUPABASE_URL` и `SUPABASE_ANON_KEY` из панели Supabase.  
   Если ключи оставить пустыми, приложение работает только в **демо-режиме** (IndexedDB).

3. **Установите зависимости** (нужен [Node.js](https://nodejs.org/) 20+; в CI — 20 и 22):
   ```bash
   npm install
   ```

## Локальный запуск приложения

Исходники — **TypeScript** (`js/**/*.ts`). Браузер их не понимает, поэтому перед
запуском нужен `tsc`: он компилирует код **на место**, рядом с каждым `.ts`
появляется `.js` (эти `.js` в `.gitignore`, коммитить их не нужно). Отдельной
папки сборки в dev-режиме нет — bundler не используется.

**Вариант 1 — dev-сервер проекта (рекомендуется):**
```bash
npm run dev
```
Компиляция запускается автоматически: `npm run dev` — это `tsc` + копирование
ассетов + генерация конфига + dev-сервер. Откройте в браузере адрес из терминала
(обычно http://localhost:8080).

Помимо статики dev-сервер выполняет и серверные функции YouTube-импорта
(`/api/yt-video`, `/api/yt-generate`) — «Карточки из YouTube» работают локально.
Ключи берутся из настроек приложения (Настройки → «Карточки из YouTube») или из
локального `.env` (см. `.env.example`). Простой `python3 -m http.server` для этого
не подходит: он не умеет POST и вернёт «Ошибка сервера (501)».

**Вариант 2 — двойной клик по `index.html`:**  
Сработает только если проект уже собран (`npm run build`). Демо-режим обычно
работает, но ES-модули и service worker могут вести себя иначе без localhost —
для полной проверки используйте сервер выше.

## Сборка и проверки

```bash
npm run build          # tsc + копирование ассетов (dev-раскладка, js/**/*.js на месте)
npm run build:bundle   # прод-сборка: tsc + esbuild-бандл в dist/ + dist/sw.js
npm run typecheck      # tsc --noEmit, без записи файлов
npm run lint           # ESLint по js/, extension/, functions/, scripts/, tests/
npm run lint:fix       # то же с автоправкой
npm run format         # prettier --write по js/**/*.ts
npm run check:format   # prettier --check, ничего не меняет
npm run sw:generate    # пересобрать список precache в корневом sw.js
```

Список `CORE_FILES` в `sw.js` генерируется обходом диска, поэтому **запускайте
`npm run sw:generate` только после `npm run build`** — иначе скомпилированных
`js/**/*.js` на диске ещё нет и список схлопнется. Что список не протух,
проверяет тест `tests/sw-precache.test.js`.

## Тесты

Unit-тесты (Vitest + happy-dom) лежат в `tests/` — 53 файла. Покрыты алгоритмы
интервального повторения (`js/lib/srs.ts`, `js/lib/fsrs-engine.ts`), хранилища
(`js/data/`), YouTube-импорт, локализация, service worker и утилиты UI.

**Запустить один раз (CI / перед коммитом):**
```bash
npm test
```

Локализация UI (`t` / `tp`):
```bash
npm run i18n:extract   # отчёт scripts/i18n-report.json
npm run i18n:check     # проверка уже мигрированных экранов (home/auth/shell)
```
Новые строки кладите в `js/lib/locales/ru.ts` (и при необходимости `en.ts`), в коде — `t('namespace.key')`.

**Запустить в режиме наблюдения** (перезапуск при изменении файлов):
```bash
npm run test:watch
```

При успехе вы увидите что-то вроде:
```
 Test Files  53 passed (53)
      Tests  344 passed (344)
```

**E2E (Playwright, `e2e/`)** — отдельно и не в CI:
```bash
npm run test:e2e:install   # один раз: скачать Chromium
npm run test:e2e
```

## Работа с Git

### Посмотреть изменения
```bash
git status          # какие файлы изменены
git diff            # что именно изменилось
git log --oneline   # история коммитов
```

### Сохранить изменения (коммит)

```bash
# Добавить нужные файлы (js/config.js добавлять НЕ нужно — он в .gitignore)
git add .

# Создать коммит с сообщением
git commit -m "Кратко опишите, зачем это изменение"
```

Примеры сообщений:
- `fix: исправить подсчёт карточек к повторению`
- `feat: добавить офлайн-очередь для облака`
- `refactor: разбить app.ts на модули`

### Отправить на GitHub (push)

```bash
# Первый раз для новой ветки
git push -u origin имя-ветки

# Дальше, если ветка уже привязана к remote
git push
```

Если работаете в `main`:
```bash
git push origin main
```

### Типичный цикл разработки

```bash
git pull                    # подтянуть свежие изменения с сервера
# ... правки в коде ...
npm run prepush             # typecheck + lint + тесты одной командой
git add .
git commit -m "описание"
git push
```
Проверить изменения локально без деплоя:
```bash
npm run dev
```

Деплой на Cloudflare Pages запускается сам — но только **после зелёного CI**
на `main` (см. `.github/workflows/`). Красная сборка в прод не уезжает.

### Важно

- **Не коммитьте** `js/config.js` — там ключи Supabase. В репозитории лежит только `js/config.example.js`.
- **Не коммитьте** `node_modules/` — он уже в `.gitignore`.
- **Не коммитьте** результат компиляции `js/**/*.js`, `dist/`, `extension/dist/` и архивы (`*.zip`, `*.tar.gz`) — всё это генерируется и уже в `.gitignore`.
- Перед push желательно прогнать `npm run prepush`.
